# Internationalisation

Interface languages: **English (default and fallback), French, Russian** (cahier des charges, Addendum A).

## Where things live

| What                                             | Where                                                                                                     |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| UI strings, push copy, errors                    | `packages/i18n/locales/{en,fr,ru}.json`                                                                   |
| Locale list, detection, Intl formatters          | `packages/i18n/src/`                                                                                      |
| Content from the database (titles, descriptions) | JSONB localized fields, resolved with `resolveLocalizedText` (`@oreva/core`) or `private.localized` (SQL) |
| Languages known to the database                  | `public.locales`                                                                                          |

## Rules

- No hardcoded UI text: ESLint fails on string literals in JSX.
- Add every key to all three files. `pnpm --filter @oreva/i18n test` checks:
  - identical keys in every language;
  - every plural form each language needs, from `Intl.PluralRules` (EN: one/other; FR: one/many/other; RU: one/few/many/other);
  - same interpolation variables;
  - no empty strings.
- Never build sentences from fragments. A short " · " separated meta line (for example "7 exercises · 6 min") is acceptable; a sentence is not.
- Dates, times, prices and distances always use the formatters in `@oreva/i18n` (Intl). Class times are shown in the **class's** time zone.
- First launch uses the phone's language if supported, otherwise English. The member can change it in Profile → Language.
- A pseudo-locale (`pseudoLocalize`) exists for layout testing; it is never shown to members.

## Adding a language later (P-06)

1. Add `locales/xx.json` with every key; the parity test lists what is missing.
2. Add `xx` to `SUPPORTED_LOCALES` and `LOCALE_INFO` (set `rtl: true` for Arabic or Hebrew).
3. Add a row to `public.locales` in a migration.
4. Add it to `supportedLocales` in `apps/mobile/app.config.ts`.
